# Bundled Public Holidays Implementation Plan

> **For agentic workers (Codex):** Execute this plan task by task, in order. Steps use checkbox syntax for tracking. Each task starts with a failing test, then the smallest change that makes it pass. Do not start a task until the previous task's tests pass and its commit exists. This document authorises no execution in the planning turn.

**Goal:** Replace the Nager.Date API with a bundled, officially sourced holiday file for Australia, New Zealand and the United Kingdom, resolved per location at read time, with organisation changes stored as small preferences.

**Architecture:** Reference JSON in `packages/availability/src/holidays/reference/data/`, validated at load. A single resolver combines reference entries, custom holidays and `public_holiday_preferences` for each location. Every holiday reader calls the resolver. Nager code, imported rows, jurisdictions and assignments are deleted.

**Tech stack:** Existing Bun, TypeScript, Prisma 7, Zod, Vitest, Next.js App Router. No new dependencies.

**Spec:** [Bundled public holidays design](../specs/2026-10-09-bundled-public-holidays-design.md). Read it, `AGENTS.md` and PRODUCT.md (`public_holidays`, `public_holiday_assignments`) before starting.

**Inspected base:** `claude/upbeat-ramanujan-fs2ax0` at the commit that adds this plan.

## Global constraints

- No runtime network calls for holiday data anywhere. After Task 10, `rg -i "nager" --glob '!docs/superpowers/**'` returns nothing.
- Every tenant query filters by `clerk_org_id` and `organisation_id`. Reference data is global and holds no tenant data.
- Australian English, no em dashes. Dates in UI as `Monday 5 October 2026`, times as `19:00`.
- Named exports only; no `any`; Zod on all form input; `Result` returns for expected failures.
- One migration per schema change, generated by Prisma. The only hand-written SQL is the data step in Task 4's empty `--create-only` migration, which contains no DDL.
- Do not invent holiday dates. Every reference entry comes from an official government public holidays page. If a page cannot be reached, stop and report which jurisdiction and year are missing; do not fill gaps from memory or third-party sites.

## Shared interfaces

```typescript
// packages/core/src/regions.ts
export type CountryCode = "AU" | "NZ" | "UK";
export const REGIONS: Record<CountryCode, ReadonlyArray<{ code: string; label: string }>>;
export function normaliseRegionCode(country: string, value: string | null): string | null; // accepts codes and labels case-insensitively ("Queensland", "qld", "Scotland")

// packages/availability/src/holidays/reference/reference-holidays.ts
export type ReferenceHolidayKind = "local" | "part_day" | "public";
export interface ReferenceHoliday {
  area: string | null;        // local only
  country: CountryCode;
  date: string;               // YYYY-MM-DD
  id: string;
  kind: ReferenceHolidayKind;
  name: string;
  region: string | null;      // null = national
  startsAt: string | null;    // "HH:mm", part_day only
}
export const PUBLIC_HOLIDAY_DATA_VERSION: string; // ISO date, bumped on every data edit
export function listReferenceHolidays(input: { country: CountryCode; region: string | null; from: string; to: string }): ReferenceHoliday[];

// packages/availability/src/holidays/resolve-public-holidays.ts
export type HolidayClassification = "non_working" | "working";
export interface ResolvedPublicHoliday {
  area: string | null;
  classification: HolidayClassification;
  date: string;
  key: string;                // reference id or "custom:<uuid>"
  kind: ReferenceHolidayKind | "custom";
  locationId: string | null;  // null = organisation-level (people without a location)
  name: string;
  origin: "custom" | "official";
  startsAt: string | null;
}
export async function resolvePublicHolidays(input: {
  clerkOrgId: ClerkOrgId; organisationId: OrganisationId; from: string; to: string;
  locationIds?: readonly string[];  // default all active locations plus organisation level
  includeHidden?: boolean;          // admin pages only; hidden items carry hidden: true
}): Promise<Result<ResolvedPublicHoliday[]>>;
```

## Review focus

1. Data integrity: unique ids, valid dates, regions from the registry, part days with times, local days with areas (Task 1 tests); spot-check of entries against the official pages (Tasks 2, 3).
2. Precedence: location preference beats organisation preference; local days never show without an opt-in; part days stay working by default (Task 5).
3. Tenancy: preferences and custom holidays never cross organisations (Tasks 5, 6).
4. Migration safety: Nager rows, jurisdictions and their assignments go; custom holidays and their location assignments survive as preferences (Task 4).
5. Feed UIDs change once, then stay stable across data releases (Task 7).
