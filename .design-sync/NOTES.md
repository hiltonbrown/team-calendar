# design-sync notes (Team Calendar design system)

## How this repo syncs

- `@repo/design-system` is raw shadcn source (no build, no `.d.ts`). `bun .design-sync/build-dist.mjs` (cfg.buildCmd) generates a sync-only package in `packages/design-system/dist/` (gitignored): `entry.ts` (runtime, every export), `types/` (tsc declaration emit; the type index exports ONE root per `components/ui/*.tsx` file, its first export), `docs/<Root>.md` (group, purpose, subpart signatures, authored preview as example), compiled Tailwind `styles.css`, fonts, and `tsconfig.bundle.json`.
- **Rerun `build-dist.mjs` before every full `package-build.mjs`**: the compiled Tailwind CSS scans `.design-sync/previews/` and the docs embed preview source, so preview edits are stale until it reruns. `preview-rebuild.mjs` does NOT recompile CSS.
- Converter command (repo root): `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules apps/app/node_modules --out ./ds-bundle`. `--node-modules` is `apps/app/node_modules` because Bun's isolated linker leaves `react-dom` out of the design-system package's own node_modules (both React 19.3.0).
- Subparts (CardHeader, DialogContent, ...) get no card of their own; they're on `window.TeamCalendar` and listed with signatures under "## Parts" in the root's `.prompt.md`.
- `DesignSystemProvider` (index.tsx) is excluded: it wraps Clerk's AuthProvider. `ThemeProvider` (next-themes) is exported instead.
- `lib/utils.ts` imports `parseError` from `@repo/observability` (Sentry + Logtail). `tsconfig.bundle.json` maps that one import to `dist/stubs/observability-error.ts` so neither ships in the browser bundle.
- Fonts: next/font sets `--font-plus-jakarta-sans` and `font-sans antialiased` on `<html>` in the product. `build-dist.mjs` ships the same as plain CSS (`@font-face` + `:root` variable + base `html` rule).
- Tailwind is compiled with `@source` over the design system, `apps/app` and `.design-sync/previews`, plus an `@source inline()` safelist for every colour token, the type scale, radii and the `elevation-*` utilities. Designs only get classes that exist in the compiled CSS (no runtime JIT).
- `extraEntries` is `./extras.ts`, generated by `build-dist.mjs`: `export * from "recharts"` plus lucide-react icons re-exported BY NAME minus recharts' names. Two plain `export *` entries made `AreaChart`/`BarChart` undefined (ESM drops names two star sources share). recharts must be on the global: a preview-bundled copy can't share recharts' React context with `ChartContainer`. Icon names that collide with components (Badge, Calendar, Command, Form, Sheet, Sidebar, ...) resolve to the component; use the `*Icon` aliases (`CalendarIcon`). recharts' `Tooltip`/`Label`/`Text` are likewise shadowed by DS components; use `ChartTooltip`.
- Declaration emit maps `@repo/observability/error` to the stub too; without it tsc emits stray `.d.ts` files into `packages/observability/`.
- Render check: Playwright 1.63.0 in `.ds-sync/` matches the cached `chromium-1243` and launches fine on this WSL box.

## Re-sync recipe

1. Re-stage the converter scripts into `.ds-sync/` (fresh clone: also `npm i esbuild ts-morph @types/react playwright@1.63.0` there).
2. `bun .design-sync/build-dist.mjs`
3. Fetch the project's `_ds_sync.json` to `.design-sync/.cache/remote-sync.json`, then `node .ds-sync/resync.mjs --config .design-sync/config.json --node-modules apps/app/node_modules --out ./ds-bundle --remote .design-sync/.cache/remote-sync.json`. Run it in the background; a full build + validate + capture takes about 10 minutes.

## Preview authoring gotchas (from the first sync's six waves)

- Compiled CSS: `build-dist.mjs` safelists the default spacing scale for spacing/sizing, responsive grid/flex/position utilities, every colour token and the type scale. Arbitrary values (`w-[440px]`) exist only when something scans them, so previews prefer scale classes or inline `style`. Grep escaped forms: `grep -F '.w-\[420px\]' packages/design-system/dist/styles.css`.
- Overlays: `open` on the root works for Dialog, AlertDialog, Sheet, Drawer, Popover, HoverCard, Tooltip, DropdownMenu (`modal={false}`). Anchored overlays need a wrapper with inline `height`. ContextMenu has no `open` prop; the preview dispatches a synthetic `contextmenu` event on mount.
- NavigationMenu opens via root `defaultValue` + item `value`; Menubar via root `value` + `MenubarMenu value`. ScrollArea needs `type="always"` for visible scrollbars.
- Previews import recharts primitives (`BarChart`, `Area`, `XAxis`, ...) from `@repo/design-system`, NOT `"recharts"`: extras reach the global via the `./extras.ts` path, so the bare specifier isn't shimmed and preview-rebuild bundles a private recharts copy (charts render empty, no error). `ChartContainer` bakes in `aspect-video`; size it with `h-64 w-full` + `style={{ aspectRatio: "auto" }}`. Pass `itemSorter={null}` to keep legend order.
- Calendar/Form/TeamTimeline use fixed dates (`new Date(2026, 9, 1)`), never `new Date()`.
- Toaster: fire `toast.success(...)` in `useEffect` with `duration: Number.POSITIVE_INFINITY`; toasts use sonner's system font (same as the product).
- ThemeProvider dark sample: wrap in `<div className="dark ...">`; `forcedTheme="dark"` recolours the whole page (`<html>` class).
- Resizable (react-resizable-panels v4): `defaultSize` numbers are pixels, pass `"38%"` strings.
- Faint by design: `--border` is 15% alpha, `--input` (#e7eae8) is used as a border colour by Checkbox, RadioGroupItem, InputGroup, InputOTPSlot, Textarea. Previews show the product as it is.

## Component defects found (reported, packages/ untouched)

- `resizable.tsx` vertical styles key off `data-[panel-group-direction=vertical]`, which react-resizable-panels v4 never sets: vertical handles render as a 1px stub, grip unrotated. `* { min-width: 0 }` collapses the `withHandle` grip.
- InputGroup invalid state draws a doubled red border (InputGroupInput keeps Input's invalid inset shadow).
- Long feed URLs clip inside InputGroup, which conflicts with the full-feed-URL rule.
- `border-input` borders and unchecked Checkbox on sheet surfaces are barely visible.

## Known render warns

- `[EXPORT_COLLISION] ./extras.ts exports 7 name(s) the main package also exports` (Badge, Calendar, Command, Form, Sheet, Sidebar, ...): lucide icon names; intended, the component wins and designs use the `*Icon` aliases.

## Re-sync risks

- `build-dist.mjs` parses each ui file's `export { ... }` block with a regex to pick roots/subparts; a file without that block falls back to `export function` names.
- The `meta` map in `build-dist.mjs` (group + one-line purpose) must gain an entry when a new ui component is added, or it lands in group "General".
- The observability stub mirrors `parseError`'s message logic; if `lib/utils.ts` imports more from `@repo/observability`, add a stub path.
